# EduSad — портал детских садов Актюбинской области

Мультисайтовая платформа: один портал плюс отдельный сайт с админкой для каждого
детского сада. Продаётся садам Актобе, деплоится на VPS в РК.

Два тарифа, описаны в `src/lib/plans.ts`, цены — в `env.planPrices`:
«Базовый» (90 000 ₸/год) — сад наполняет сайт сам; «С наполнением»
(150 000 ₸/год) — то же плюс наполнение по запросу сада. Сайт в обоих
одинаковый, отличие одно — кто его ведёт. Собственный домен (.kz или edu.kz) не входит
ни в один. Тексты тарифов нигде не дублируются: главная, тарифы,
заявка, оферта и договор берут их из `plans.ts`.

Язык интерфейса, документации, комментариев и коммитов — **русский**.

## Команды

```bash
pnpm db:up        # PostgreSQL в Docker (порт 5433, не 5432)
pnpm db:setup     # миграции + демо-сады
pnpm dev          # разработка
pnpm typecheck && pnpm lint
pnpm test         # 44 юнит-теста (vitest)
pnpm test:e2e     # 34 сквозных (playwright, поднимает сервер сам)
```

Открывать **http://bobegim.local:3000**, не `localhost` — сад определяется по домену.
Домены прописаны в hosts: `bobegim.local`, `sad12.bobegim.local`, `kunshuaq.bobegim.local`,
`ertegi.bobegim.local`.

Доступы после `pnpm db:setup`: портал `admin` / `admin-bobegim-2026`,
сад `sad12-admin` / `sad12-2026`.

## Как устроено

Одно приложение обслуживает портал, сайты всех садов и обе админки.

`src/middleware.ts` смотрит на заголовок Host: домен портала идёт в группу `(portal)`,
любой другой переписывается в `/s/<host>/...` — группу `(tenant)`. И поддомен сада,
и купленный садом собственный домен лежат в одной таблице `Domain`, поэтому путь
резолва один на оба случая.

Изоляция данных — `src/server/db/scope.ts`: репозиторий, который физически не умеет
обратиться к контенту без `tenantId`. **Прямые вызовы `prisma.post`, `prisma.media`
и подобных в коде сайта и админки сада запрещены** — только через `scoped(tenantId)`.
Для update/delete есть `assertOwned()`.

## Грабли, на которые уже наступали

Каждая стоила часа отладки. Не повторяйте.

**`redirect()` из server action не проходит через middleware.** Путь вроде
`/admin/posts` разрешается в маршруты портала, а не сада, и сотрудник получает 404.
Поэтому действия возвращают `{ redirectTo }` (см. `src/lib/action-state.ts`),
а переход делает клиент через `ActionForm` / `window.location.assign`.

**Cookie сессии привязана к домену.** Поэтому «Войти как сад» не может просто
поставить её на портале: сессия передаётся одноразовым токеном через
`/admin/enter` и там же ротируется.

**`COOKIE_SECURE=false` обязателен при работе по http.** Иначе браузер молча
отбрасывает cookie, и вход выглядит как «неверный пароль».

**Внутренний префикс `/s/` заблокирован в middleware.** Без этого с домена портала
открывался бы сайт любого сада по чужому адресу.

**Статика с новым расширением должна быть в исключениях `matcher` middleware.**
Иначе запрос к `/images/…/flag.mp4` с домена сада переписывается под тенанта
(`/s/<домен>/…`) и отвечает 404, хотя файл на диске есть. Сейчас исключены
png, jpg, jpeg, gif, webp, svg, ico, css, js, woff, woff2, mp4, webm.

**Сырой SQL обходит `scoped()`.** Поиск построен на tsvector, а значит на
`$queryRaw` — единственном месте, где можно случайно прочитать чужой сад.
Поэтому запросы поиска живут в `src/server/db/search.ts`, где `tenantId`
подставляется параметром, а наружу торчит только `scoped(tenantId).search()`.

**Генерируемую колонку Prisma норовит сломать.** У `searchVector` в схеме стоит
`@default(dbgenerated())`: без него `prisma migrate dev` видит `GENERATED ALWAYS AS`
как обычный DEFAULT, генерирует лишнюю миграцию с `DROP DEFAULT` и падает на ней.

**После `prisma migrate dev` перезапустите `pnpm dev`.** Работающий сервер держит
в памяти прежний клиент Prisma, и новое поле схемы даёт `Unknown argument` —
выглядит как ошибка в коде, хотя на диске клиент уже перегенерирован.

**`unicode-range` у Google Fonts не доказывает, что буква есть.** Гарнитура
объявляет подмножество `cyrillic-ext`, а глифов ә ғ қ ң ұ ү һ і ө в ней может
не быть вовсе — браузер молча подставит их из системного шрифта, и казахский
текст поедет вперемешку с чужими буквами. На этом попались Baloo 2 (нет ни
одной казахской буквы) и Manrope (нет ә ғ қ ң ұ). Проверять надо измерением
глифа: отрисовать символ в canvas выбранной гарнитурой и заведомо
несуществующей — совпали ширины, значит буквы нет.

**База проекта на порту 5433.** На машинах разработчиков часто уже стоит свой
PostgreSQL на 5432, и Prisma молча подключается к нему.

**Обновлённый сертификат не доезжает сам.** Certbot кладёт новый файл
на диск, а nginx и postfix держат старый в памяти до перезагрузки: сайт
отдавал бы просроченный сертификат при полностью исправном обновлении.
Перезагрузку делает хук `/etc/letsencrypt/renewal-hooks/deploy/reload-services.sh`;
его наличие видно в админке портала, раздел «Сервер».

**Незнакомый домен уходил на чужой сайт.** Без `default_server` nginx отдаёт
запрос с неизвестным Host первому загруженному блоку — это был parser.e04.kz
с его сертификатом. Теперь первым стоит `/etc/nginx/sites-enabled/00-default`:
по http — заглушка «Сайт не настроен» (`/var/www/default-site`, код 404),
по https — `ssl_reject_handshake`, и браузер сам уходит на http. В нём же
открыт `/.well-known/acme-challenge/` из `/var/www/acme`: сертификат для
нового домена сада выпускается ещё до того, как у домена есть свой блок.

**`.env` вне репозитория.** `git pull` его не обновляет — после изменения
`.env.local.example` файл нужно перезаписать вручную.

## Соглашения

- **Двуязычие.** У текстовых полей пары `...Kk` / `...Ru`. Вывод через `pick(locale, kk, ru)` —
  если перевода нет, показывается второй язык. Требование закона РК «О языках».
- **HTML от пользователя** санитизируется при сохранении (`sanitizeContent`), не при выводе.
- **Изображения** проходят через `saveUpload` — пересжатие в WebP и снятие EXIF
  (иначе с фото детей уезжают GPS-координаты сада).
- **Аудит.** Сброс паролей, вход «под садом», смена статусов пишутся через `audit()`.
- **Подписка.** Льготных дней нет. Последний оплаченный день сад работает
  (`periodIsOver` в `src/lib/subscription-period.ts` — одно правило и для
  приложения, и для утреннего скрипта), со следующего дня админка только
  на просмотр, а утренняя проверка в 09:00 ставит статус `SUSPENDED`: сайт
  закрыт, вместо него `/unavailable` — «временно недоступен» с причиной
  (неоплата), телефоном сада и строкой для его администрации. Обращения
  не принимаются. Оплата в карточке сада возвращает `ACTIVE`. Права
  проверять через `assertCanEdit(session)`: он учитывает и подписку,
  и статус. Так же это описано в оферте (8.2) и договоре (7.3) — менять вместе.
- **Поиск** — полнотекстовый, на генерируемых базой колонках `searchVector`
  (миграция `fulltext_search`). Словаря казахского в PostgreSQL нет, поэтому текст
  индексируется дважды: конфигурацией `russian` (по основе слова) и `simple`
  (как есть), а запрос ищется и по основе, и по началу слова — `наурыз:*`.
  Разбор запроса и подсветка найденного — `src/lib/search-query.ts`. Фрагмент
  приходит из `ts_headline` размеченным управляющими символами, а не готовым HTML:
  собранную из текста сада разметку в страницу не подставляем.
- **Карты.** Координаты сада определяет геокодер Яндекса при сохранении профиля
  (`src/server/maps/yandex.ts`, ключ в `YANDEX_GEOCODER_KEY`) — заведующая своих
  координат не знает. Введённые руками не затираются: одинаковых названий улиц
  в Актобе хватает, и точнее человека геокодер не будет. Сады, заведённые раньше,
  доберёт `pnpm maps:geocode`. Карта везде одна — виджет Яндекса в iframe:
  ключа не требует и к домену не привязан, а это важно, потому что у сада
  может быть собственный домен. Был 2ГИС (`RouteMap`), но его виджет
  `firmsonmap` ждёт идентификатор организации в справочнике, которого
  у сада нет, и вместо карты показывал «Something went wrong». Ссылка
  на 2ГИС осталась кнопкой — им часто пользуются для навигации.
- **Карта каталога** интерактивная, если задан `YANDEX_MAPS_KEY` (JavaScript API
  2.1, ключ уезжает в браузер), и виджетом в iframe — если нет. Метки
  пронумерованы так же, как карточки. У бесплатного тарифа 100 запросов
  в сутки, поэтому карта строится по нажатию, а не на каждый заход: иначе
  сотня родителей израсходовала бы лимит, и сто первый увидел бы пустое место.
  Запасной виджет по той же причине — не формальность.
- **SEO.** `robots.txt` и `sitemap.xml` есть и у портала, и у каждого сада —
  какой отдать, решает домен. У портала каждая страница — на двух языках
  (казахская — `?lang=kk`), в карте сайта обе версии с `hreflang`; canonical
  и hreflang страниц — `portalAlternates` из `src/lib/seo.ts`. Главная выводит
  эти теги сама: у адреса с путём «/» Next теряет `?lang=kk`.
- **Язык админки** хранится в `User.locale`, а не в cookie: заведующая заходит
  с разных устройств, и выбор должен ехать за ней. Переключатель — в шапке
  (`AdminLocaleSwitch`), после смены клиент делает `router.refresh()`. Полная
  перезагрузка тут не годится: она обрывает начатые переходы. Тексты интерфейса
  живут рядом с разметкой словарём `const T = { ключ: { kk, ru } }` — тем же,
  что на сайтах садов. На странице входа пользователя ещё нет, поэтому там язык
  берётся из адреса (`?lang=kk`), как на публичной части.
- **Подписи перечислений и даты** — `src/lib/labels.ts`. `formatDate`,
  `formatDateTime` и `formatAgeRange` принимают язык вторым аргументом;
  по-казахски год идёт первым — «2026 жылғы 3 қыркүйек».
- **Основной язык сайта сада** — `Tenant.defaultLocale` (изначально казахский,
  меняется в «Оформлении»). Без `?lang=` сайт открывается на нём, второй язык —
  с параметром. Ссылки на сайте сада строить только через `withLocale`
  из `src/server/tenant/context.ts`: она знает язык сада на время запроса.
  Версия из `src/lib/i18n` считает основным русский — это язык портала.
  Демо-сады в сидах русские: на них написаны сквозные тесты.
- **Язык портала** — в адресе (`?lang=kk`), как на сайтах садов. Шапка и подвал
  живут в `PortalChrome` и вставляются самими страницами: layout в Next
  не получает searchParams. Cookie было бы проще, но тогда поисковик увидел бы
  одну версию страницы вместо двух.
- **Главная портала продаёт сайты садам** (с 23.09.2026), родительские
  страницы (`/catalog`, `/parents`, `/news`) остались на прежнем оформлении
  (`PortalChrome`), но с главной на них не ведут. `/pricing`, `/connect`
  и `/apply` — временные перенаправления на разделы главной (`?plan=`
  отмечает тариф в форме); `/offer`, `/contacts` и `/guide` — в оформлении
  главной (`SalesPage`). Манера «нежная» (29.09.2026, образец G из
  bobegim-design): утреннее небо, пастель, облака, воздушные шарики;
  шрифты Comfortaa, Nunito и рукописный Caveat (проверены на казахские
  буквы). Вместо нарисованных картинок — настоящие снимки демо-сада
  «Балапан» и его админки на языке страницы (`public/images/sales/*.{ru,kk}.webp`):
  поменялся заметно сайт сада или админка — переснимите. Разметка и весь
  текст — на сервере (`src/app/(portal)/page.tsx`), шапка и подвал —
  `SalesChrome`, вкладки — `SalesTabs`, движение — `SalesMotion` (gsap,
  ScrollTrigger и Lenis грузятся только на главной; первый экран виден
  сразу, прячется и всплывает только то, что ниже окна; уборка при уходе
  со страницы обязательна).
  Цены — для частных садов, у государственных своя: рядом с ценами всегда
  `STATE_PRICE_NOTE` из `plans.ts`. Стили — `sales/sales.css`, каждое
  правило под корнем `.sales`: CSS страницы остаётся в документе после
  перехода по ссылке, и общие имена (`.nav`, `.form`, `.plan`) задели бы другие
  страницы. Кнопки там `.sbtn`, анимации `sales-*` — `.btn`, `spin` и `pulse`
  уже заняты. Заявка — тот же `submitLead`, что у `/apply`.
  После изменения зависимостей на сервере перед сборкой нужен `pnpm install`.
- **Внешний вид портала** задаёт `data-skin="portal"` на `<html>` — его ставит
  только layout портала. Скин переопределяет не бренд-цвета, а всю нейтральную
  базу: тёплая бумага вместо почти-белого, тёплый чёрный вместо серо-синего,
  крупные скругления, Geist и Manrope вместо Baloo 2 и Nunito Sans. Сайты садов
  он не затрагивает — там по-прежнему работает только `data-palette`. Блок
  в `globals.css` стоит **перед** `[data-a11y='on']`: режим для слабовидящих
  обязан перебивать скин, иначе контрастная версия останется бежевой.
- **Уведомления владельцу** — `notifyOwner()` из `src/server/notify/mail.ts`:
  новая заявка, блокировка входа после пяти ошибок. Письма уходят через postfix
  на той же машине (`edusad@e04.kz`, без пароля), адрес получателя — `NOTIFY_EMAIL`.
  Функция никогда не бросает: не ушла почта — заявка всё равно сохраняется.
  О падении сайта приложение сообщить не может, поэтому этим занимается сторож
  `/usr/local/bin/edusad-watchdog` (таймер каждые 5 минут, шлёт через sendmail
  в обход приложения). Письмо о сбое — после двух неудачных проверок подряд:
  выкладка обновления перезапускает приложение, и будить из-за этого незачем.
  Сводку по подпискам шлёт `pnpm subscriptions:check` по таймеру в 09:00.
- **Резервные копии — только база**, без загруженных файлов (решение владельца
  25.09.2026: места нет, файлы после загрузки не меняются). Каждую ночь в 03:30
  `vsesad-backup.timer` запускает `/usr/local/bin/vsesad-backup` (в репозитории
  `deploy/vsesad-backup`): `pg_dump -Fc` в `/var/backups/vsesad`, проверка
  оглавлением, 30 дней, письмо при сбое, итог — в `/var/lib/edusad/backup.json`
  для раздела «Сервер». Восстановление — `vsesad-restore <файл>` (сначала сам
  снимет копию текущего состояния). Скрипты копируются на сервер руками, как
  `vsesad-certs`. Копии на том же сервере: от потери сервера они не спасают.
- **Инструкция для садов** — три формата из одного демо-сада «Балапан»:
  ролики и пошаговые кадры на `/guide` (робот проходит сценарии
  `scripts/guide/scenarios.ts`, `pnpm guide:record`) и PDF на двух языках
  (текст — `scripts/guide-content.ts`, снимки — `pnpm guide:shots`, сборка —
  `pnpm guide:pdf`, ссылки на файлы — `GUIDE_PDF` из `src/lib/guide.ts`).
  Снимается только на локальной базе. Ролики в git не входят: на сервер —
  `scp` и перезапуск (docs/DEPLOY.md, раздел 10). Поменялся экран
  админки — перезапишите его ролик и снимки.
- **Новости из Instagram** — раздел админки сада «Из Instagram»
  (`admin/(shell)/instagram`). Официального доступа к Instagram нет и не будет,
  а список постов аккаунта сервер без входа не получает (внутренний адрес
  отвечает 401). Поэтому ссылки на посты вставляет сотрудник, а сервер
  открывает страницу каждого поста с User-Agent превью ссылок
  (`src/server/instagram.ts`) и берёт из мета-тегов аккаунт, тип, подпись,
  день и обложку (разбор — `src/lib/instagram.ts`, с тестами). Время поста
  Instagram не отдаёт — ставим полдень. Обложка сразу сохраняется к нам:
  ссылки их CDN через несколько дней протухают. Ссылка на пост — в `videoUrl`
  (проигрыватель Instagram показывает и ролик, и карусель), по ней же
  ловим повтор. Подпись идёт на своём языке, машинный перевод не выдумываем.
  Разовый перенос по готовому списку — `scripts/import-video-posts.ts`.
- **Поле выбора файла** в админке — только `FileInput`
  (`src/components/admin/FileInput.tsx`): надпись браузерного поля — на языке
  Windows, и в казахской админке стояла английская «Choose File».
- Разделы сайта описаны в `src/lib/sections.ts`, шаблоны — в `src/lib/templates.ts`.
  `Section.isVisible = false` — раздел **убран из меню**, а не выключен:
  по ссылке его страницы открываются (иначе объявление с главной из
  «скрытого» раздела вело в 404). В карту сайта такие разделы не попадают.
  Страница «не найдено» сада ведёт на его же главную (`<a href="/">`,
  не Link: 404 отрисована по внутреннему адресу `/s/<домен>/…`).
- **Документы** лежат в папках, папки вкладываются друг в друга, как в проводнике
  (`DocumentFolder.parentId`). Всё дерево считается в памяти по плоскому списку
  (`src/lib/doc-tree.ts`), открытая папка — параметр адреса `?folder=`, а не
  раскрывашка: ссылку на папку можно переслать, поисковик видит каждую.
  Удалённая папка не уносит содержимое — оно поднимается на уровень выше.
  Перенос готового дерева с Google Диска — `pnpm docs:import <домен> <файл.json>`
  (`scripts/import-doc-tree.ts`, повторный запуск безопасен). Манифест
  с идентификаторами файлов в репозиторий не кладём.
- **Оформление сада** — независимые настройки, каждая атрибутом на `<html>`
  (layout сайта): шаблон главной, палитра (`data-palette`, 19 штук + «свой
  цвет»), узор (`data-pattern`), пара шрифтов (`data-font`), форма элементов
  (`data-shape`), цвет шапки (`data-header-style`). Плюс «готовые стили»
  (`PRESETS`) — только заполняют форму. «Свой цвет» строит палитру из одного
  цвета (`src/lib/colors.ts`) и сам сгущает его до контраста 4.5 с белым.
  Любая палитра обязана пройти `tests/unit/palettes.test.ts`: белый текст
  на основном цвете и тёмный на плашке — контраст от 4.5, без исключений.
  Новый шрифт — только после проверки глифов (см. «unicode-range…»).
- **Индивидуальные темы** — `src/themes/` (как сделать — `src/themes/README.md`).
  Тема одного сада при общем движке: своя главная, шапка, подвал и CSS.
  Назначает только владелец портала (`Tenant.themeCode`), перекрывает шаблон
  и настройки «Внешнего вида» сада; шрифты темы — `fonts` в каталоге. Готовые:
  `dala`, `akvarel`, `konstruktor`, `akku` (лебединое озеро) — макеты
  из Google Stitch; `oyin` (детская площадка, у сада «Аққу») — по образцу
  владельца, рисунок первого экрана в `public/images/themes/oyin`; `resmi`
  (как сайт государственной организации: цепочка, «Важно», последние
  документы — для этого главная получает `documents` и `menu`); `akorda`
  («Акорда», вплотную к akorda.kz: полоса шапки с орнаментом, синий блок
  с флагом, гербом и надписью «Официальный сайт», главная новость белой
  карточкой с листанием на радиокнопках, таблетка разделов, тёмный подвал;
  картинки и видео флага сняты с akorda.kz и лежат в
  `public/images/themes/akorda`). **Герб и флаг — государственные символы:
  тема показывает их только государственному саду, у частного
  (`profile.isPrivate`) тот же блок на синем фоне без герба и без флага.**
  Видео флага идёт от 960 px и без `prefers-reduced-motion`, иначе стоит
  неподвижная картинка. `uyshik` («Үйшік», домик) — сад как кукольный дом
  в разрезе: разделы сайта — комнаты (картинки в `public/images/themes/uyshik`,
  комнат столько, сколько у сада разделов), на крыше название, во дворе
  новости на бельевой верёвке, объявления на указателе, фото полароидами.
  `uyshik-anim` («Үйшік — анимация») — копия «Үйшік», у которой первый
  экран — «ролик», которым управляет прокрутка: сцена залипает, облака
  расходятся, солнце встаёт, дом вырастает, камера едет вниз по дому,
  в комнатах по очереди загорается свет. **Без JavaScript** — CSS
  scroll-driven animations (`animation-timeline: view()`): свои клиентские
  компоненты в темах запрещены тестом. Включается при поддержке браузера,
  на экране от 900×620 и без «меньше движения»; иначе — тот же пейзаж
  неподвижно. Слои (солнце, облака, холмы, луг, деревья) — вырезки
  из Stitch в `public/images/themes/uyshik-anim`, комнаты — у «Үйшік».
  Снимки витрины делаются с «меньше движения» (`design-shots.ts`), иначе
  на снимке во всю длину вышел бы кадр из середины ролика.
  Десять тем вплотную к десяти популярным дизайнам садов (цвета, формы,
  раскладка — как у образца; фото и рисунки сгенерированы в Stitch,
  `public/images/themes/<код>`; тексты и данные — сада): `shuaq`,
  `jasyl`, `aspan`, `kuanysh`, `kosaq`, `erekshe`, `nur`, `gulder`,
  `mamyq`, `kunbagys`. У каждой своя шапка, подвал и `Doodles.tsx`.
  Яркие цвета образцов сгущены до контраста 4,5:1, а там, где цвет
  оставлен ярким, на нём только крупный текст (порог 3:1) — это записано
  в шапке `theme.css` каждой темы. Фото сада (`CoverOr`) стоит во втором
  экране, первый — картинка темы: на ней держится сходство с образцом.
  Чего у сада нет — блок не рисуется или берёт настоящую замену (нет
  кружков — группы или направления ГОСО; нет тарифов — группы). Портрет
  заведующей — только настоящий, из карточки педагога. Вырезки (дети,
  игрушки) — PNG с прозрачным фоном: Stitch рисует их на #FF00FF или
  на белом, фон снимается скриптом (bobegim-design/themes10/v2).
  Класс `<код>-cta` занят кнопкой шапки — полосы записи называть иначе.
  Карточек бывает меньше, чем в образце: ряды — flex с центровкой,
  а не сетка на фиксированное число колонок.
  На главной этих тем — то, что сад публикует: объявления, лента из девяти
  новостей (`newsFeed`; шаблонам по-прежнему уходят шесть в `news`),
  последние три фото галереи (`photos`, `scoped().albums.latestPhotos`)
  и последние документы таблицей, как в «Ресми». Блоки общие —
  `src/components/site/theme-blocks.tsx`, заголовок секции рисует тема.
  Тест тем требует, чтобы главная любой темы выводила объявления
  и новости: опубликовал сад — увидели родители.
  **Витрина дизайнов** — `/designs` и `/designs/<код>` на портале (меню,
  подвал, кнопка в «Как выглядит»): темы с описанием `showcase` в каталоге,
  снимки во всю длину на компьютере и телефоне, при наведении прокрутка,
  «Открыть вживую» — `https://demo.<портал>/?theme=<код>`. Примерка `?theme=`
  на боевом работает **только на демо-саде** (middleware и `activeTheme`
  сверяют хост): там выдуманные данные, настоящих детей на витрине быть
  не должно. Снимки — `pnpm designs:shots` (с боевого демо), файлы
  в `public/images/designs`, размеры — `src/lib/design-shots.json`; тест
  не пропустит тему с `showcase` без снимков. Поменялась тема — переснимите.
  Закреплённое (`isPinned`) стоит первым везде — в админке, в новостях
  и объявлениях на главной и на странице раздела — и помечено «Закреплено».
  CSS темы действует только при `data-theme` на `<html>`. Версия для
  слабовидящих запоминается в cookie сайта (`edusad-a11y`, `src/lib/a11y.ts`),
  и сервер при ней темы не рисует вовсе — `activeTheme` отдаёт null, сайт
  в стандартной доступной вёрстке, а `data-theme-own` говорит переключателю,
  что при выключении режима нужна перезагрузка. Раньше режим жил только
  в localStorage: CSS темы снимался, а разметка оставалась, и значки темы
  раздувались на весь экран. Упавшая тема заменяется стандартной
  частью (`ThemeBoundary`) и шлёт письмо. Тесты не пропустят CSS без префикса
  темы и импорты базы, сессий и server actions внутри темы. Примерка
  `?theme=код` — только при `THEME_PREVIEW=1`, на боевом сервере её нет.

- **Блоки главной** — `src/components/site/home-blocks.tsx` (счётчики, распорядок,
  педагоги, кружки, группы, полоса записи) плюс `ReviewList`, `PriceList`,
  `FaqList` из `sections`. Данные главная передаёт в `HomeProps` всем
  шаблонам и темам; темы собирают из них раскладку по структуре популярных
  сайтов садов. Блок без данных не рисуется, счётчики (`src/lib/home-stats.ts`)
  — только из настоящих данных. Новые данные сада: отзывы родителей (только
  настоящие, с согласия), стоимость (частные сады), короткий распорядок для
  главной — админка «Отзывы», «Стоимость», «Распорядок (главная)».

- **Демо-сад** — `demo.edusad.kz`, «Балапан» с выдуманными данными: его
  показывают заведующим. Помечен `Tenant.isDemo`: сайт открыт, но в каталог,

## Ограничения предметной области

- Домен `.kz` обязан указывать на сервер **в Казахстане**, иначе регистратор
  приостановит его через 10 дней. Персональные данные тоже должны храниться в РК.
- Собственный домен сада — в зоне `.kz` (`nursat.kz`) или `edu.kz`
  (`nursat.edu.kz`, только для организаций образования). Сад покупает
  и оформляет его сам, мы только помогаем настроить. В текстах портала так
  и написано — «покупаете сами, а мы поможем настроить».
- **Подключение домена** делает не приложение, а `deploy/vsesad-certs.sh`
  (на сервере `/usr/local/bin/vsesad-certs`, таймер каждые 10 минут, root).
  Берёт домены из таблицы `Domain`, проверяет A-запись по публичному DNS,
  выпускает сертификат (с `www.`, если у него тоже A-запись на нас), пишет
  конфиг nginx и результат в карточку: `certStatus`, `certExpiresAt`,
  `lastError`. Удалённый из карточки домен убирает вместе с сертификатом.
  У приложения прав на nginx и certbot нет намеренно. Скрипт в репозитории —
  после правки его нужно скопировать на сервер руками, `git pull` этого
  не делает. Почту для Let's Encrypt он берёт из `NOTIFY_EMAIL` в `.env`:
  репозиторий публичный.
- Очередь в сад ведёт государство через Darabala.kz — мы на неё только ссылаемся.
  Реализовывать свою нельзя: попадём под требования к государственным системам.

## Чего пока нет

Онлайн-оплата (модель подписки готова, эквайринг подключается без переделки).

Двуязычие доведено до конца: портал, сайты садов и обе админки говорят
на двух языках. Новый экран обязан заводить свой словарь `T` — иначе
интерфейс снова начнёт разъезжаться.
